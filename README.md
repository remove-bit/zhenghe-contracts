# 正合合同（ZhengHe Contracts）

<p align="center"><img src="assets/logo.png" width="120" alt="正合 Logo"></p>

> **不多不少，正合所需** · 房地产销售合同全生命周期管理 · **零依赖 · 零配置 · 一条命令启动**

正合CRM 的兄弟产品。沿用「Node.js 22 内置 SQLite + 原生前端 + 零 npm 依赖」的技术路线，把房地产销售合同从**认购、审批、签约、网签备案、回款、变更到归档**串成一条可追溯的链路。

## 为什么这么做

市面上的房地产合同管理，主流做法不是孤立地管一份 PDF，而是嵌入「客户—房源—价格—认购—签约—回款—交付」主线。调研中重点参考了：

- **明源云客 / 世诚云 / 思源**：售楼场景的认购—签约—回款闭环、电子签章、网签备案对接、多级权限与销控联动。
- **法大大 / e签宝 / 契约锁**：以 OpenAPI 方式嵌入电子签章、身份核验与存证（本项目先用「备案编号登记」模拟该环节，预留接口位）。
- **金蝶 / 用友**：合同—回款—凭证的业财一体思路，回款计划与实收流水分离建模。
- **住建部建房规〔2020〕4号及成都、武汉等地网签备案办法**：签约即备案、生成备案编码、房源状态自动置为已售；变更/注销按城市口径留痕。

产品形态上参照正合CRM：`admin / manager / sales / legal / finance` 五级角色、数据范围隔离、操作审计、只读 SQL 查询与一键备份。

## 快速开始

只需 **Node.js ≥ 22.5**（使用内置 `node:sqlite`，无需 npm install）。

```bash
git clone <仓库地址>
cd zhenghe-contracts
node server.js
```

打开 <http://localhost:3001> 。首次启动自动建库、灌入演示数据（4 个项目 / 24 套房源 / 10 位客户 / 14 份合同）。

## 功能模块

| 模块 | 能力 |
| --- | --- |
| **工作台** | 签约金额、回款、审批、风险、可售房源六大指标；合同状态分布；逾期回款与待办 |
| **合同台账** | 合同编号自动生成；按状态/类型/项目/折扣筛选；搜索客户、合同号、房号；CSV 导出；详情多标签页 |
| **审批流程** | `草稿 → 审批中 → 待生效 → 已生效 → 已备案`；按金额自动路由销售经理→法务→财务，≥300 万增加总经理；逐节点通过/驳回留痕 |
| **网签备案** | 登记备案编号与日期；房源状态自动更新为「已备案」；备案超期预警 |
| **回款管理** | 付款方式生成回款计划（一次性/按揭/分期）；实收流水与计划分离；部分收款、逾期识别、收款凭证 |
| **房源销控** | 楼栋/房号/面积/面价；可售、锁定、认购、签约、备案、不可售状态；合同流程自动联动，退房自动释放 |
| **变更管理** | 更名、换房、价格变更、补充协议、退房解除；审批通过后自动执行并保留版本链 |
| **合同模板** | 统一范本与条款库，版本管理；高风险表述扫描 |
| **风险预警** | 回款逾期、备案超期、认购转签超期、审批滞留、折扣低于 90%、高风险条款六类规则 |
| **统计报表** | 签约趋势、合同状态、项目货值与去化、团队业绩 |
| **系统管理** | 五级角色权限、数据隔离、操作审计、只读 SQL 查询、整库导出与备份 |

## 合同状态机

```
草稿 --提交审批--> 审批中 --各节点通过--> 待生效 --双方签章--> 已生效 --网签备案--> 已备案
  |                    |
  |                    +--任一节点驳回--> 已驳回 --修改后重提--> 审批中
  +--删除
已备案 / 已生效 --变更审批--> 解除 --> 已解除（房源恢复可售）
```

## 数据模型

`users`、`projects`、`units`、`customers`、`contracts`、`approvals`、`payments`、`receipts`、`changes`、`templates`、`tasks`、`audit_logs` 共 12 张表。核心关系：

- 一份合同关联一个客户、一个项目、至多一套房源；
- 回款计划（`payments`）与实收流水（`receipts`）分离，支持部分收款；
- 审批记录、变更记录与审计日志独立成表，保证过程可追溯；
- 房源状态由合同状态机驱动，避免一房多卖/退房未释放。

## 配置

| 环境变量 | 说明 | 默认值 |
| --- | --- | --- |
| `PORT` | 服务端口 | 3001（与正合CRM 的 3000 错开） |
| `HOST` | 监听地址 | 0.0.0.0 |
| `CONTRACT_DB` | 数据库路径 | `data/contracts.db` |
| `CONTRACT_SECRET` | 登录签名密钥 | 自动生成并存 `data/secret` |

## 备份与恢复

```bash
npm run backup
# 或
node backup.js --keep 7
node backup.js --dir D:\backups
node backup.js --no-zip
```

Web 端「数据库」页也提供一键备份、整库导出和只读 SQL 查询。备份 zip 内含 `contracts.db`、`secret` 与恢复说明。

## 与生产落地的距离

本项目是**可运行的完整原型**：业务逻辑、数据模型和权限流程都已落地；以下外部能力以登记/模拟方式预留，接入真实服务时替换对应环节即可：

- 电子签章与实名核验（法大大/e签宝/契约锁 OpenAPI）；
- 住建/房管网签备案接口（按城市逐城适配，含变更口径差异）；
- 资金监管账户、银行按揭放款与税局开票接口；
- 短信/企业微信消息推送、移动端审批。
